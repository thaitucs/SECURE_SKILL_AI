# Step 1 - Safety, mode and capabilities

**Goal:** know what you are allowed to do before touching anything.

## 1.1 Determine the mode

- Default to `PLAN` (read-only).
- `APPLY` only when the user gives approval IDs after seeing a plan in this session, or points
  to an existing `secure-check-report/SECURE_CHECK_PLAN.txt` and approves items from it.
- `QUICK` when the user asks for a fast check or the skill runs in CI.

If the user says "fix everything" before any plan exists, run `PLAN` first and explain that
approval happens on the plan. This protects the user from surprise changes.

## 1.2 Determine your capabilities

| Capability | If yes | If no |
|------------|--------|-------|
| Read files | Normal flow | Ask the user to paste the file tree and key files (configs, env examples, server entry, auth, upload code). |
| Run commands | Use `scripts/` and project build/test commands | Manual checklists only; tell the user which verifications they must run. |
| Write files | Write reports to `secure-check-report/` | Print the plan in chat. |
| Git available | Use a branch | Backup copy (APPLY only). |

## 1.3 Backup plan (needed before APPLY, prepared during PLAN)

During `PLAN`, only check and record the situation:
- Is it a git repo? Is the working tree clean (`git status --porcelain`)?
- What is the current branch?

Before the first change in `APPLY`:
- **Git, clean tree:** `git switch -c secure-check/<yyyy-mm-dd>`.
- **Git, dirty tree:** stop and ask: commit, stash, or continue on top of the uncommitted work.
- **No git:** propose `git init` + an initial commit, or a full copy of the folder to
  `<project>_backup_<yyyy-mm-dd>/` outside the project. Wait for the answer.

- **Backup copy location:** always outside the project folder and outside any git working
  tree, so it can never be committed or pushed.

Never run `git push`, `git reset --hard`, `git clean`, force operations, or history rewriting
(`filter-repo`, BFG) yourself. If history contains secrets, explain the procedure in the
plan as a "You must do" item. Never push the `secure-check/<date>` branch either - it stays
local unless the user pushes it.

## 1.5 Local-only outputs (golden rule 11)

Every file SECURE_CHECK generates stays on the user's machine. It is **never staged,
committed or pushed**, in any mode, even when the user asks to commit or push the project.

| Generated by SECURE_CHECK | Where | How it stays local |
|---------------------------|-------|--------------------|
| Plan, reports, `CHANGES_LOG.md`, `raw/` | `secure-check-report/` | `secure-check-report/.gitignore` = `*` + `.git/info/exclude` |
| Quarantined files + `README.txt` | `_quarantine/` | `_quarantine/.gitignore` = `*` + `.git/info/exclude` |
| Backup copy (no-git projects) | `<project>_backup_<yyyy-mm-dd>/` | outside the project and outside any repo |
| Work branch | `secure-check/<yyyy-mm-dd>` | local branch, never pushed by the AI |

Do this **the first time** you create `secure-check-report/` (PLAN, QUICK or APPLY):

1. Create `secure-check-report/.gitignore` with exactly:
   ```
   # SECURE_CHECK: this folder is generated and LOCAL-ONLY.
   # It must never be committed or pushed. This file makes git ignore the whole folder.
   *
   ```
   (It ignores itself too, so not even this file shows up in `git status`.)
2. Git repo: append `/secure-check-report/` and `/_quarantine/` to `.git/info/exclude`
   (use `git rev-parse --git-path info/exclude` to find it in worktrees). This file is local
   to the clone and is never committed. Do not add duplicate lines.
3. Run `git ls-files secure-check-report _quarantine`.
   - Empty: good.
   - Not empty (an earlier run was committed): `!!` item - propose `CFG-xx`
     `git rm -r --cached secure-check-report _quarantine` (files stay on disk). If those
     commits were pushed, add a `YOU-` item: the reports are in the remote history and
     describe vulnerabilities - treat them like leaked secrets (`references/secret-patterns.md`).
4. Confirm with `git status --porcelain`: no path under these folders may appear.

Steps 1-3 are allowed in read-only `PLAN` mode: they touch only the skill's own output folder
and git's local, uncommitted exclude file - never a tracked project file. `scripts/run_all.py`
performs them automatically; still run step 4.

Chat-only AI (cannot write files): tell the user to save the plan outside the repo, or inside
a `secure-check-report/` folder with the `.gitignore` above, and not to commit it.

## 1.4 Scope

- Ignore: `node_modules/`, `vendor/`, `.venv/`, `venv/`, `__pycache__/`, `dist/`, `build/`,
  `.next/`, `.nuxt/`, `out/`, `target/`, `bin/`, `obj/`, `Pods/`, `.gradle/`, `.dart_tool/`,
  `coverage/`, `.git/` (but **do** note if `.git/` would be deployed).
- Build output folders are ignored for code review but **checked** for leaked secrets and
  source maps when they are committed or deployed.
- Lock files are read for dependency review, not for code review.

## Exit criteria

Mode known · capabilities known · git status recorded · scope defined · output folders
local-only (1.5).
